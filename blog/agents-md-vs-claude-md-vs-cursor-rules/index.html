AGENTS.md vs CLAUDE.md vs Cursor Rules: Which Do You Need?

Published 2026-10-16 · 3 min read · by AgentKit Co

If you use an AI coding agent, you have probably been told to "write a rules file". Then you looked and found four or five different file names. This guide explains what each one is, which tools read it, and the smallest setup that works for most people. Everything here was checked against each tool's own documentation on 2026-10-16, but these tools change fast, so use the links at the end to confirm.

The one idea behind all of them

A coding agent starts every session knowing nothing about your project. An instruction file is the short note you would give a new teammate: how to run things, how the code is organized, what to avoid. The files differ only in which tool reads them and how precisely you can scope them.

The files

File What it is Who reads it
AGENTS.md Plain Markdown, no required fields. Can also live in subfolders; the closest file to the one being edited wins. Cursor, GitHub Copilot, OpenAI Codex, Zed, Warp, Windsurf and many others. Gemini CLI and Aider need a one-line setting.
CLAUDE.md Markdown instructions for Claude Code. Project, personal (~/.claude/CLAUDE.md) and private (CLAUDE.local.md) versions. Claude Code
.claude/rules/*.md Topic files. With a paths: list in the frontmatter they load only when matching files are in play. Claude Code
.cursor/rules/*.mdc Cursor project rules with description, globs and alwaysApply frontmatter. A plain .md file there is ignored. Cursor
.github/copilot-instructions.md Repository-wide Copilot instructions. Path-specific files go in .github/instructions/ and use an applyTo glob. GitHub Copilot

The old single-file .cursorrules is described in Cursor's docs as legacy, so new projects should skip it.

A setup that works for most people

  1. Write one AGENTS.md at the repository root. Put commands, layout, conventions and boundaries in it.
  2. If you use Claude Code, add a CLAUDE.md whose first line is @AGENTS.md. That is Claude Code's import syntax, and it means you maintain the shared rules in one place. Anthropic's docs currently say Claude Code reads AGENTS.md by itself only when there is no CLAUDE.md in the working directory or above, which is why the bridge file is the safe choice.
  3. Move area-specific rules into scoped files instead of growing the root file: a Cursor .mdc rule with globs, a Claude .claude/rules/ file with paths, or a Copilot .instructions.md file with applyTo.
@AGENTS.md

## Claude Code
- Use plan mode before changing anything under `src/billing/`.

How long should the file be?

Shorter is better. Anthropic suggests keeping each CLAUDE.md under 200 lines, and Cursor suggests rules under 500 lines. A good target for the root file is 60 to 120 lines. Longer files use up context and make it more likely that a rule gets ignored.

Instruction files are guidance, not enforcement

An agent can still ignore a line. Claude Code's docs say plainly that it treats these files as context rather than enforced configuration. If something must never happen, such as touching production data, back the instruction with a permission setting, a hook or a git check.
